# 설계 우선 원칙

> 원본: `blueprints/design-principles.md`

## 1. 설계 우선 원칙

**작업 크기에 맞는 절차를 밟는다.** 요청만으로 할 일이 분명한 작업은 바로 구현하고 검증한다.
결정할 것이 남아 있는 작업은 요구사항 구체화 → 설계 → 구현 순으로 진행한다.

- **설계는 사용자 승인 후 구현한다**
- 더 나은 방법이 있으면 설계 단계에서 **능동적으로 대안을 제안**한다

**절차 자체는 전담 도구에 맡긴다** — 이 규칙은 단계나 산출물 형식을 따로 정하지 않는다.

- `superpowers` 플러그인이 있으면 그 흐름(구체화 → 설계 → 계획 → 구현 → 검토)을 따른다
- superpowers가 없으면 기본 plan mode로 계획을 세우고 승인받은 뒤 구현한다
- 설계 문서 위치는 절차 도구가 정한 곳을 따른다 (superpowers: `docs/superpowers/specs/`)
- 설계 대비 구현 일치도를 수치로 볼 때는 `gap-detector` 에이전트에 설계 문서 경로를 넘긴다

## 2. 문서 디렉토리

- `docs/stack/` — 프로젝트에서 합의된 기술 스택별 패턴·컨벤션 (`<언어 또는 프레임워크>.md`)
- `docs/source/` — 코드 설명 문서. 소스 트리와 동일한 구조로 생성/갱신한다
  - 파일명: 소스 확장자를 `.md`로 변경 (예: `uart.c` → `docs/source/src/drivers/uart.md`)
  - 내용: 모듈 목적, 주요 함수/클래스 역할, 의존 관계, 주의사항
  - 코드 주석과 중복하지 않는다 — 주석은 "왜(why)", 문서는 "전체 그림(what/how)"
