# ADR-002: 슬림화 — 개발 절차를 superpowers에 위임

- **날짜**: 2026-11-17
- **상태**: **채택**
- **결정자**: inseok + Claude

## 맥락

`adt`는 2026-04(v0.4.x)와 2026-07(v0.5.0·v0.6.0)에 두 번 갱신했지만 실제로는 쓰이지 않았다.
그 사이 팀에서 배포한 `rkit` 플러그인을 쓰게 됐는데, rkit도 특정 기능을 골라 쓴 기억은 없고
프로젝트마다 `.rkit/` 상태 폴더를 만들어 `.gitignore` 관리가 번거로웠다.

한 세션에 `rkit`, `superpowers`, `adt` 글로벌 규칙이 동시에 걸려 "작업을 어떤 절차로 진행하라"는
지시가 세 갈래로 들어왔다. `adt`의 에이전트 12개 중 11개는 superpowers의 스킬과 역할이 겹쳤다.

상세: [설계서](../superpowers/specs/2026-11-17-adt-slim-revival-design.md)

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|--------|------|------|
| A: 슬림화 — 절차는 superpowers에 맡기고 `adt`는 고유 영역에 집중 | 유지 범위가 작다. 절차 지시 충돌이 사라진다 | superpowers에 의존한다 |
| B: 자립형 — 파이프라인 유지·최신화, rkit PDCA 요소 추가 흡수 | 다른 플러그인 없이 동작한다 | 유지량이 가장 많다. superpowers와 충돌이 계속된다 |
| C: 최소 갱신 — 구조 그대로, 플랫폼 변화만 반영 | 가장 빠르다 | 안 쓰게 된 원인이 그대로 남는다 |

## 결정

**A: 슬림화.** 혼자 유지하는 도구라 범위가 작아야 계속 살아 있고, 다른 도구가 대신하지 못하는
부분만 남겨야 실제로 손이 간다.

함께 정한 원칙:

1. `adt`는 개발 절차를 지시하지 않는다. 절차는 superpowers, 없으면 기본 plan mode.
2. `adt`는 프로젝트 디렉토리에 숨김 상태 폴더나 상태 파일을 만들지 않는다.
   실행 상태가 필요해지면 `${CLAUDE_PLUGIN_DATA}`를 쓴다.
3. 상시 개입(SessionStart 주입, 출력 스타일 강제)을 늘리지 않는다.
4. 다른 플러그인의 도메인 지식은 미리 옮기지 않고, 실제로 필요해진 시점에 한 건씩 가져온다.

## 결과

- 에이전트 12개 → 1개 (`gap-detector`만 유지, 입력은 지정한 설계 문서 경로)
- 스킬 11개 → 10개 (`/adt:review` 삭제)
- 템플릿 4개 → 1개 (`decision.template.md`만 유지)
- `blueprints/design-principles.md`와 글로벌 규칙 `workflow.md`에서 단계 프리셋·산출물 디렉토리·
  서브에이전트 파이프라인 삭제
- rkit에서 가져온 것은 응답 말미 "다음 추천" 한 줄뿐이다
- **ADR-001의 채택 항목 4 "에이전트 템플릿 참조"는 이 결정으로 대체된다** (참조하던 에이전트와
  템플릿이 삭제됨). 항목 1 중 Plan·Design·Report 템플릿도 함께 삭제됐다
- 호환성 깨짐: `adt:designer` 등 삭제된 에이전트를 호출하던 흐름은 더 이상 동작하지 않는다
