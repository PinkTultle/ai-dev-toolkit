# 지침 계층과 메모리

> 도구 무관 공유 지식 — 어떤 지식을 어디에 두는가
> Claude Code 기준 검증 버전: **v2.1.220**

---

## 1. 배치 결정

지식을 쓰기 전에 **어디에 둘지 먼저 정한다.** 잘못된 위치는 컨텍스트만 먹고 지켜지지 않는다.

| 성격 | 위치 | 로드 시점 |
|------|------|----------|
| 매 세션 참인 짧은 사실 (빌드 명령, 컨벤션, 구조) | `CLAUDE.md` | 항상 |
| 특정 경로에서만 필요한 지침 | `.claude/rules/*.md` + `paths` | 해당 파일 접근 시 |
| 여러 단계로 이뤄진 절차 | 스킬 | 호출 시 |
| 반드시 강제해야 하는 규칙 | 훅 / `permissions` | 해당 시점 |
| AI가 스스로 발견한 학습 | auto memory | 항상 (색인만) |

> CLAUDE.md의 한 항목이 **절차**로 자라났다면 스킬로 옮긴다.
> **일부 디렉토리에서만** 의미가 있다면 경로 스코프 rule로 옮긴다.

## 2. CLAUDE.md

### 2.1 계층

넓은 범위부터 로드되며, 나중에 로드된 것이 뒤에 놓인다(= 더 구체적인 것이 우선).

| 범위 | 위치 |
|------|------|
| 조직 관리 정책 | Linux/WSL `/etc/claude-code/CLAUDE.md`, macOS `/Library/Application Support/ClaudeCode/CLAUDE.md`, Windows `C:\Program Files\ClaudeCode\CLAUDE.md` |
| 사용자 | `~/.claude/CLAUDE.md` |
| 프로젝트 | `<root>/CLAUDE.md` 또는 `<root>/.claude/CLAUDE.md` |
| 개인 로컬 | `<root>/CLAUDE.local.md` (gitignore) |

상위 디렉토리의 CLAUDE.md는 시작 시 전부 로드되고, **하위 디렉토리의 것은 그 안 파일을 읽을 때
지연 로드**된다. 실제로 무엇이 로드됐는지는 `/context`로 확인한다.

### 2.2 작성 규칙

- **200줄 이내**를 목표로 한다. 길수록 컨텍스트를 먹고 준수율이 떨어진다
- 검증 가능하게 구체적으로 쓴다 — "포맷 정리" ✘ / "들여쓰기 2칸" ✔
- 모순되는 지침을 남기지 않는다. 두 규칙이 충돌하면 임의로 하나가 선택된다
- 코드베이스에서 유추 가능한 것(디렉토리 목록, 의존성 나열)은 넣지 않는다.
  **관례에서 벗어나는 점, 함정, 이유**를 남긴다
- `@path/to/file`로 다른 파일을 가져올 수 있으나 **컨텍스트는 줄지 않는다** — 시작 시 전부 로드된다
- 블록 주석(`<!-- ... -->`)은 컨텍스트에 주입되기 전에 제거된다 — 유지보수 메모용으로 쓴다

### 2.3 다른 도구와 공유

Claude Code는 `AGENTS.md`를 직접 읽지 않는다. 이미 `AGENTS.md`를 쓰는 저장소라면
`CLAUDE.md`에서 가져온다:

```markdown
@AGENTS.md

## Claude Code
(도구 전용 추가 지침)
```

## 3. `.claude/rules/`

`.claude/rules/**/*.md`가 재귀적으로 탐색된다. 한 파일에 한 주제.

```markdown
---
paths:
  - "src/**/*.{ts,tsx}"
  - "tests/**/*.test.ts"
---

# API 개발 규칙
```

| 구분 | 동작 |
|------|------|
| `paths` 없음 | 시작 시 무조건 로드 (`.claude/CLAUDE.md`와 같은 우선순위) |
| `paths` 있음 | 매칭되는 파일을 **읽을 때** 로드 |

- 사용자 rules(`~/.claude/rules/`)가 먼저, 프로젝트 rules가 나중에 로드된다(프로젝트 우선)
- 심볼릭 링크를 지원한다 — 공용 규칙을 한 곳에서 관리하고 각 프로젝트에 링크할 수 있다
- glob에서 `[`는 문자 클래스로 해석된다. 리터럴 `[`는 `\[`로 이스케이프한다

## 4. Auto memory

AI가 세션을 넘어 스스로 축적하는 학습 노트. 사람이 쓰는 CLAUDE.md와 **역할이 다르다.**

|  | CLAUDE.md | auto memory |
|--|-----------|-------------|
| 작성자 | 사람 | AI |
| 내용 | 지시와 규칙 | 발견한 사실과 패턴 |
| 범위 | 프로젝트/사용자/조직 | 저장소 단위 (워크트리 공유) |

### 4.1 위치와 로드

```
~/.claude/projects/<project>/memory/
├── MEMORY.md        ← 색인. 매 세션 앞 200줄 또는 25KB만 로드
├── debugging.md     ← 주제 파일. 필요할 때만 읽음
└── ...
```

- `<project>`는 git 저장소 기준 — 모든 워크트리가 하나의 메모리를 공유한다
- **머신 로컬**이다. 다른 워크스테이션과 동기화되지 않는다
- 끄기: `/memory` 토글, `autoMemoryEnabled: false`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`

### 4.2 운용 규칙

- `MEMORY.md`는 **항목당 한 줄인 색인**으로 유지한다. 상세는 주제 파일로 내린다.
  한계를 넘으면 넘친 부분은 다음 로드에서 조용히 버려진다
- **저장소가 이미 기록하는 것은 저장하지 않는다** — 코드 구조, 과거 수정 이력, CLAUDE.md 내용
- 상대 날짜("지난주")는 절대 날짜로 바꿔 저장한다
- 메모리는 **쓰인 시점의 사실**이다. 파일·함수·플래그를 언급하는 메모리는 **사용 전에 실재를 확인**한다
- 서브에이전트는 부모 세션의 auto memory를 **상속받지 않는다**(포크는 예외).
  에이전트 전용 메모리는 정의 파일의 `memory` 필드로 따로 켠다

### 4.3 이 저장소의 지식 축적 원칙과의 관계

`base-directives.md`의 "AI는 지침에 임의로 내용을 추가하지 않는다"는
**사람이 관리하는 지침 파일**(`docs/stack/`, `.claude/rules/`, CLAUDE.md)에 적용된다.
auto memory는 AI 자신의 작업 노트이므로 이 제약 밖이며, 대신 위 4.2 규칙을 따른다.
auto memory에 쌓인 내용이 팀에 공유할 가치가 있으면 **사용자 합의를 거쳐** 지침 파일로 승격한다.
